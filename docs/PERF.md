# 性能实测记录

> 数据来自 `python main.py --perf`（或 `RustyMoment.exe --perf`），结果同时写入
> `%APPDATA%\RustyMoment\logs\perf-report.md`。换机器后跑一遍就有你自己的数字。

## 测试环境

| 项 | 值 |
| --- | --- |
| 系统 | Windows 11 25H2（10.0.26200） |
| CPU | Intel Core Ultra 7 255HX（20 线程） |
| 内存 | 16GB |
| Python | 3.13.13（源码运行）/ PyInstaller onedir（打包运行） |
| OBS | 32.2.2 + obs-websocket 5.7.4（本地回环） |
| 音频 | Realtek 板载，48kHz 立体声输出 |

## 结果

| 项目 | 指标 | 备注 |
| --- | --- | --- |
| 空闲（3 秒无操作，源码运行） | CPU **0~0.5%**，内存 **19MB** | GUI 主窗口打开、定时器 200ms 刷新 |
| 空闲（打包 exe，`--perf`） | CPU **0%**，内存 **44.4MB** | PyInstaller onedir 会多加载一批 DLL，属正常 |
| 麦克风采集 + VAD（5.2 秒） | CPU **2.4%**，内存 +0MB（总计 46MB），167 块 0 丢弃 | 16kHz 单声道，含 VAD 逐帧处理 |
| VAD 切句 | 处理 4.5 秒音频 **4.9~7.1ms**（约 **630~925× 实时**） | 纯 numpy，不含识别 |
| 播放启动（解码 + 打开流） | 平均 **165~172ms**，最慢 244ms | 1 秒 wav；AAC 整首解码另见下 |
| AAC 解码（216~302 秒整曲） | **0.47~0.66 秒** | PyAV 后端，48kHz 立体声 |
| 语音识别 tiny（1.5 秒音频） | 加载 6.2 秒（含首次下载），单句 **351ms** | CPU int8 |
| 语音识别 tiny（3~5 秒 TTS 语料） | 单句 **373~470ms** | 阶段 2 实测 |
| 语音识别 small（3~5 秒语料） | 单句 **2118~2350ms** | 准确率明显更高 |
| AI 本地 qwen3:8b（CPU int8） | 单句 **5.4~8.9 秒** | 思考型模型，含 ~500 字推理 |
| OBS 控制往返（GetVersion） | 平均 **< 5ms**（本地回环） | 连接建立约 100~300ms |
| 触发到出声（阶段 1 实测） | **约 288ms** | 含 OBS 静音请求 + 音频流启动 |

## 怎么读这些数字

- **常驻开销很小**：19MB 空闲、采集时 2.4% CPU —— 边玩游戏边开着它基本感觉不到。
- **VAD 极其便宜**：800× 实时，意味着 30ms 一帧的处理只花几十微秒，不会占用游戏帧。
- **瓶颈在语音识别**：tiny 0.35~0.47 秒/句已经接近"说完就判"；small 要 2 秒以上，会明显延迟。
- **AI 是最贵的一层**：本地 8B 模型 5~9 秒，只能"事后整活"；要实时就用云端小模型（未在本机联调）。
- **触发到出声约 0.3 秒**：主要是打开音频流的固定成本，无法完全消除。
